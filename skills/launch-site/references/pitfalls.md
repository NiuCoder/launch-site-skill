# 上线踩坑清单

来自两次真实上线（Cloudflare Workers + D1/R2 + better-auth + Waffo/PayPal + AI 视频生成）。每条格式：**症状 → 原因 → 做法**。遇到新坑按同样格式追加到对应小节。

## 登录（Google / better-auth）

**L1. 从带 `#` 的页面点 Google 登录，什么都没发生。**
原因：better-auth 拒绝带 hash 的相对回调地址（`callbackURL=/#workspace`），返回 403 `INVALID_CALLBACK_URL`，前端没有显示这个错误。
做法：回调地址用绝对的同源 URL（`new URL(path, location.origin).href`），并把社交登录的错误显示给用户。

**L2. One Tap 登录成功了，页头还是显示"登录"。**
原因：SSR 渲染的页头没有会话；客户端拿到凭证后没有刷新。
做法：One Tap 成功后整页刷新一次。

**L3. One Tap 出现过一次后再也不出现。**
原因：把"跳过"（FedCM 冷却、没有 Google 会话）和"拿到凭证"都当成用户主动关闭，记进了存储；2 秒延迟内会话重新获取又取消了提示；错误被吞掉。
做法：只记住用户明确关闭的情况；effect 只依赖标量值；初始化成功后才锁定；回调错误用 `console.warn` 加 toast 显示出来。

**L4. 用密码注册过的邮箱，用 Google 登录失败。**
原因：better-auth 返回 `account_not_linked`。
做法：登录页识别这个错误码，提示用户先用密码登录。

**L5. 控制台有 Google FedCM `NetworkError`，以为是新版本的问题，回滚了。**
原因：这个错误在旧版本里也有，和本次发布无关。
做法：怀疑回归时，先用上一个版本复现一次再决定是否回滚。

**L6. 线上回调和可信来源指向 localhost。**
原因：`VITE_APP_URL` 在构建时写进产物；`.env.local` 里的 localhost 优先于生产值。
做法：部署命令先把 `.env.production` 读进 shell 再构建（ShipAny 的 `cf:deploy` 就是这样做的）；部署后检查线上 HTML 里的 canonical 和 OAuth 跳转地址。

**L7. Lighthouse 报 React #418（hydration 不一致）。**
原因：认证会话 store 或公共配置查询在懒加载路由 hydration 之前就有了结果，客户端首次渲染和 SSR 不一样。
做法：用 `useSyncExternalStore` 区分 hydration 阶段：SSR 和首次 hydration 保持 pending，挂载后再返回真实数据。不要用关闭 hydration 警告的方式掩盖。

## Cloudflare

**C1. 绑定自定义域名报 409（code 100117）。**
原因：根域名上还有旧的代理 A 记录。
做法：先记下要删记录的 ID、IP、TTL、proxied 状态，作为回滚依据；经用户确认后只删这几条，不要动 MX/SPF/DKIM。

**C2. 以为在部署生产，实际把测试版发上去了（或者反过来）。**
原因：测试构建会覆盖被 git 忽略的 `wrangler.jsonc`；直接跑 `wrangler deploy` 用的是最后一次构建的目标。
做法：生产和测试各用一条封装好的命令，每次都重新拷贝对应的 wrangler 配置再构建；部署前打印 Worker 名字。

**C3. 后台配置里的密钥全部解不开。**
原因：`CONFIG_ENCRYPTION_KEY` 被轮换，或者本地值和 Worker secret 不一致；Worker secret 设置以后读不回来。
做法：key 生成后立即存进被忽略的本地文件；写加密配置前，先用本地 key 解密一条线上已有的密文，确认一致。

**C4. 把 PEM 私钥当成加密 key 上传了。**
原因：变量名填错。
做法：加密 key 超过 128 个字符或者是 PEM 格式时直接拒绝。

**C5. 样片上传到了私有桶，或者差点打开私有桶的公开访问。**
原因：文档里写的桶名和实际用途不一致：一个公开桶放样片，一个私有桶放用户素材。
做法：上传前用 `wrangler r2 bucket list` 和 `r2 bucket dev-url get <bucket>` 确认哪个是公开桶；私有桶永远不开公开访问。预检阶段误传的文件要告诉用户，不要擅自删除。

**C6. 中间件里改重定向响应的头，结果返回 500。**
原因：`Response.redirect()` 返回的 headers 是不可变的。
做法：用 `new Response(null, { status: 301, headers: new Headers({ Location }) })` 自己构造。

**C7. 下线的路由用编码或大小写变体仍能访问（`/%61dvisor`、`/ADVISOR`）。**
原因：拦截规则匹配的是原始 pathname，而路由器会先解码、忽略大小写。
做法：匹配前先解码、去掉控制字符、统一大小写、合并重复斜杠、去掉尾斜杠和语言前缀；解码失败返回 400。只改用于判断的字符串，不改交给业务处理的 Request。

**C8. 视频 Range 请求返回 200 和整个文件，而不是 206。**
做法：只按实测结果描述，不要宣称支持断点或已经提速。

**C9. `wrangler d1 migrations list` 偶尔报 `fetch failed`。**
做法：这种情况不能当作"没有待应用的迁移"，要重跑一次。

**C10. `wrangler tail` 加 `--sampling-rate 1` 连不上。**
做法：去掉这个参数。

## 支付（Waffo / PayPal）

**P1. 网站做完了，生产环境却不能收款。**
原因：商户业务审核（KYB）没通过，商店 `prodEnabled=false`。审核表要求法定姓名和收款银行账户持有人一致，还要填税务居住地，只能本人填写。
做法：第 0 阶段就提交审核。

**P2. Waffo SDK 读不了私钥文件。**
原因：下载的 PEM 文件里夹着说明文字。
做法：在内存里提取 Base64 私钥部分再交给 SDK；不要另存一份明文。

**P3. 把配置里的环境改成 production，调用的还是测试环境。**
原因：SDK 调用的环境由 API Key 决定，配置里的环境字段只控制 webhook 验证和商品发布。
做法：生产要用独立的生产 API Key。

**P4. webhook 越注册越多。**
原因：每次运行初始化脚本都会再注册一个；初始化中途失败时，已经成功的远程操作不会回滚。
做法：运行前去控制台看已有的 webhook；失败后先检查远程状态，再决定是否重试。

**P5. SDK 更新商店的官网和客服邮箱，没有报错，但字段没变。**
做法：所有远程写操作都回读一次确认；没生效就不算完成，改到控制台里手动填。

**P6. 改了本地价格，结账页还是旧价格。**
原因：本地价格不会同步到远端商品。
做法：价格改动后同步商品并回读；在测试收银台核对金额。已有订阅保留原续费价格，不要覆盖旧订阅商品。

**P7. 回调处理失败，支付商却不再重试。**
原因：处理失败时仍返回 HTTP 200。
做法：付款状态和积分写入数据库后才返回 2xx，失败返回 5xx。另外，接口用 HTTP 200 加 `code: -1` 表示错误时，不能只看 HTTP 状态判断成败。

**P8. 切换商户或商店后，商品映射指向别的商店。**
做法：切换商户、商店或环境时，自动关闭支付并清除旧映射，验收后再显式打开。

**P9. AIGC 产品过不了支付商的合规审核。**
原因：Waffo 要求披露具体的底层模型、生成前和展示前都要审核、保留审核记录、公开禁止内容和举报方式。只审核提示词不够。
做法：在关于页写明模型；输入和输出都要审核，失败时关闭（不展示、退还冻结的积分）；记录审核结论。

**P10. 浏览器打不开收银台页面。**
原因：浏览器保存的站点权限阻止了访问。
做法：请用户检查设置；不要换浏览器或换域名去绕过。

**P11. 生产 bootstrap 报 "No test version found"，脚本停在第一个商品。**
原因：用生产 API Key 创建的商品已经是生产版本；`publish()` 的作用是把测试版本推到生产，对没有测试版本的商品会失败。脚本中途失败，已创建的商品不会回滚，后面的商品和 webhook 都没做。
做法：生产 bootstrap 不调用 `publish()`。中途失败后先用 GraphQL 只读查询商品（`onetimeProducts { id name hasProdVersion }`）和 webhook（`stores { storeWebhooks { id url testMode } }`），再用 `--existing=<本地ID>:<PROD_ID>` 复用已创建的商品继续，不要重新创建。

**P12. 本地丢了 `CONFIG_ENCRYPTION_KEY` 原值。**
原因：Worker secret 推上去以后读不回来，本地又没留备份。
做法：生成时就让用户备份到密码管理器。已经丢了就不要换 key：密钥类配置改用 Worker secret，并删掉 D1 里的同名行（见 shipany-template.md"没有加密 key 原值时"）。

**P13. 生产私钥填进了别的变量名。**
症状：`.env.production` 里 `CONFIG_ENCRYPTION_KEY` 有 1600 多个字符（正常是 44 个）。
原因：用户手动整理 env 文件时放错了行。
做法：`site:config` 会拒绝长度超过 128 或 PEM 形状的加密 key；交接后用 `awk` 只看变量名和长度核对，发现异常请用户自己改，不要替用户猜。

## SEO 与内容

**S1. 只有首页有 OG 图、Twitter 卡片和语言 alternate。**
做法：每个页面模板都要补齐；用 `smoke.sh` 检查所有页面，不要只看首页。

**S2. 首页第一个标题是横幅里的 H2，排在 H1 前面。**
做法：横幅标题改成普通段落，外观不变。

**S3. 文案和实际能力不一致。**
例子：写着"AI 会去掉车标"，但模型做不到；写着"未使用原始素材"，但实际用了。
做法：功能或策略改动后，全站搜索相关说法（FAQ、落地页、法务页、上传提示），一起改。

**S4. IndexNow 一直沿用模板的 key。**
做法：每个站生成自己的 key 和对应的 key 文件路由。

**S5. 需要被外部服务读取的媒体放在 `/api/` 下面，而 robots 屏蔽了 `/api/`。**
做法：这类资源放到不受 robots 屏蔽的路径，用签名和有效期保护，并加 `noindex`/`no-store`。

## 演示素材（AI 生成的视频和图片）

**A1. 8 次高清渲染全部不合格，跑了一整夜，没有一条能上线。**
原因：验收标准（画面中不能有任何车标和文字）超出了模型的稳定能力，而且是渲染完才发现。
做法：开工前和用户定好验收标准，先用 1–2 次低成本渲染试探模型能不能稳定做到，做不到就当场调整标准，或者放弃这个特技。见 content-assets.md。

**A2. 某个特技始终出不了合格的片子。**
做法：设定止损线（例如 3 轮仍不合格就下线这个特技），不要无限重试。上一次上线最后下线了 kickflip，只保留 wall ride。

**A3. 重试时被重复扣费。**
做法：提交付费任务前先把意图写进本地记录；脚本可以中断后接着跑；每个案例的重试次数有上限。

**A4. 海报图是黑的。**
原因：截的是视频第 0 帧。
做法：从画面中段截图，并检查平均亮度。

**A5. 供应商的输出审核拒绝了成片，但不说原因。**
做法：记录日志 ID，不要绕过审核，也不要重复提交付费任务；把这次结果当作失败处理。

## 验收与流程

**V1. 截图标着 768/1440px，实际只有 390px。**
原因：视口模拟没生效。
做法：截图前读取 `window.innerWidth`，截图后核对图片宽度；不对就改用 CDP 设置视口。

**V2. 新克隆的项目测试失败。**
原因：生成文件（路由树、i18n 编译结果）还没生成。
做法：先跑一次 build。

**V3. Python 的 urllib 请求线上被返回 403。**
原因：Cloudflare 拦截了这个 UA。
做法：用 curl 或真实浏览器检查，这不算线上故障。

**V3b. `dig` 查到的 IP 是 `198.18.x.x`。**
原因：本机代理（fake-IP 模式）在回答 DNS，不是真实记录。
做法：用 `dig @1.1.1.1 <domain>` 或 Cloudflare API 查真实记录，不要按这个结果删改 DNS。

**V4. 安全扫描报 HIGH，人工看都是示例连接串和测试假密钥。**
做法：逐条人工复核后再放行；扫描范围限定在本项目，不要扫到父目录的兄弟项目。

**V5. "测试通过"被当成了"已上线"。**
做法：每条结论都标明级别：代码通过、已部署、业务验收（见 SKILL.md）。

**V6. 写给另一个 agent 的任务单在阶段之间等待确认，一等就是一晚上。**
做法：任务单里写清楚预算上限、停止条件和是否需要等待确认；可以连续执行的就明确写"连续执行"。

# AI 演示素材：先定标准和预算，再开渲染

上一次上线中，案例视频的生成和验收用了约 15 小时，占整个项目一大半时间。失败原因不是脚本，而是验收标准超出了模型的稳定能力，而且渲染完才发现。

## 开工前和用户确认

| 项目 | 例子 |
|---|---|
| 每个特技 / 场景要几条 | 每个 2 条，首页最多 8 条 |
| 必须满足 | 主体车辆颜色和外形与输入一致；动作完整；没有车牌号码 |
| 可以接受 | 车辆原有车标；背景里的品牌 |
| 直接淘汰 | 落地姿态明显不对；画面里有人脸；有其他品牌的大面积文字 |
| 总预算 | 例如 8 次高清渲染，或供应商额度 X |
| 每个案例最多重试 | 2 次 |
| 止损线 | 一个特技 3 轮仍不合格就下线，或者改为只展示其他特技 |
| 输入图片的授权 | 自己拍的 / AI 生成的 / 有授权的图库；来源不明的不上传给供应商 |

把确认结果写进项目文档（例如 `docs/case-acceptance.md`），之后的每一轮都按它判断。

## 流程

1. **试探**：每个特技先用 1–2 次低成本渲染（快速档或低分辨率），看模型能不能稳定满足"必须满足"那一栏。做不到就当场和用户调整标准，或者放弃这个特技。
2. **批量渲染**：
   - 提交付费任务前先把意图（案例 ID、seed、参数）写进本地记录，脚本可以中断后接着跑，不会重复扣费；
   - 达到预算上限就停，不追加。
3. **验收**：
   - 用 ffprobe 确认分辨率、时长、有没有音轨；
   - 每条抽 4 帧，再做一张 20 帧的联系表检查动作；
   - 按标准逐条给出结论和理由，记进表格。
4. **发布**：
   - 海报从画面中段截取，并检查平均亮度，避免黑图；
   - 视频做 faststart；
   - 只上传到公开桶；
   - 视频旁标注"AI 生成的演示"，并说明与任何品牌无关；
   - 只给页面上可见的主要案例写 VideoObject 结构化数据。
5. **文案同步**：模型的实际表现和文案冲突时（例如文案写会去掉车标，实际不会），改文案或改产品，不要让两者不一致。

## 没有合格素材时

- 保留现有的占位素材，不要把不合格的片子当作案例发布；
- 报告里写明"网站已上线，案例未达标"，不要写成"案例已上线"。
